# Deploying `django-impatient/moviereviews` to PythonAnywhere

Puts the [`django-impatient`](../django-impatient/README.md) book's
`moviereviews` project on the public internet, for free, at
`https://<your-username>.pythonanywhere.com`.

## Why this is different from [`deploy/README.md`](README.md)

Render and GitHub Pages (used for `data-serve`/`d3-interactive-web`)
both redeploy automatically on `git push`, driven by config files
committed to this repo (`render.yaml`, the Pages workflow).
**PythonAnywhere has no equivalent for a free account** - no Blueprint-
style deploy-from-repo, no webhook, no API token this repo could use
without you creating one yourself. Every step below happens through
your own PythonAnywhere login (a Bash console in the browser, and the
**Web** tab), the same way `deploy/README.md`'s "First-time setup"
already accepts for Render/GitHub Pages: *"there's no way to fully
script account creation on a free tier you don't already have API
credentials for"* - PythonAnywhere goes further and has no scriptable
deploy step at all, even after the account exists.

This file is a guide to follow by hand, not a script to run - unlike
`render.yaml`, nothing here executes on its own from a `git push`.
Redeploying a code change means repeating the "Everyday workflow"
steps below yourself each time.

## What was changed in this repo to make this possible

- [`moviereviews/settings.py`](../django-impatient/moviereviews/moviereviews/settings.py):
  `SECRET_KEY`, `DEBUG`, and `ALLOWED_HOSTS` now read from environment
  variables (`DJANGO_SECRET_KEY`, `DJANGO_DEBUG`, `DJANGO_ALLOWED_HOSTS`),
  falling back to the original local-dev values when those aren't set -
  so `manage.py runserver` locally is completely unaffected, and a
  deployment sets its own via the WSGI file (step 5 below).
  `SECURE_SSL_REDIRECT`/`SESSION_COOKIE_SECURE`/`CSRF_COOKIE_SECURE` are
  derived from `DEBUG` the same way. `STATIC_ROOT` was also added, for
  `collectstatic` (step 4) - unused by `runserver`, which serves static
  files itself when `DEBUG=True`.
- [`django-impatient/moviereviews/requirements-pythonanywhere.txt`](../django-impatient/moviereviews/requirements-pythonanywhere.txt):
  just `Django==5.2.17` and `Pillow==12.3.0` (pinned to match the
  repo-root lockfile), instead of the full repo-root `requirements.txt`
  - that file locks *every* stage in this monorepo (Scrapy, Flask,
  matplotlib, pymongo, ...), which would be slow to install and mostly
  wasted space against PythonAnywhere's free-tier disk quota for an app
  that only needs two of those packages.
- `.gitignore`: added `django-impatient/moviereviews/staticfiles/`
  (collectstatic's output - regenerated by step 4, never committed),
  alongside the already-ignored `db.sqlite3`/`media/`.

## One-time setup

**1. Create a PythonAnywhere account** (if you don't have one) at
[pythonanywhere.com](https://www.pythonanywhere.com) - the free
"Beginner" plan is enough for this. Note your username; it determines
your URL (`<username>.pythonanywhere.com`) and every path below.

**2. Open a Bash console** (**Consoles** tab -> **Bash**) and clone the
repo:

```bash
git clone https://github.com/hovinh/web-development-learning-lab.git
```

**3. Create a virtualenv and install this stage's dependencies** (not
the repo-root `requirements.txt` - see "What was changed" above):

```bash
mkvirtualenv --python=python3.11 moviereviews-venv
pip install -r web-development-learning-lab/django-impatient/moviereviews/requirements-pythonanywhere.txt
```

`mkvirtualenv` (PythonAnywhere's own helper, from `virtualenvwrapper`)
creates it at `/home/<username>/.virtualenvs/moviereviews-venv` and
activates it in the current console - the **Web** tab will ask for that
same path in step 6.

**4. Set up the database and static files**, still inside that
virtualenv:

```bash
cd web-development-learning-lab/django-impatient/moviereviews
python manage.py migrate
python manage.py collectstatic --noinput
```

`migrate` creates a fresh `db.sqlite3` here - **PythonAnywhere's free
tier has persistent disk** (unlike Render's, see
[`deploy/README.md`](README.md)'s "Free-tier tradeoffs"), so unlike
that setup, this database keeps its data between deploys rather than
needing to be rebuilt from committed data every time. Optionally seed
it with sample data the same way local dev does (see
[`django-impatient/README.md`](../django-impatient/README.md)'s log):

```bash
python manage.py seed_movies
python manage.py seed_news
python manage.py createsuperuser
```

**5. Generate a real secret key** for this deployment (never reuse the
one in `settings.py` - see that file's comment on why):

```bash
python -c "import secrets; print(secrets.token_urlsafe(50))"
```

Copy the output; you'll paste it into the WSGI file next.

**6. Create the web app** (**Web** tab -> **Add a new web app**):

- Choose **Manual configuration** (not the "Django" wizard option -
  that scaffolds a *new* project; this repo already has one) -> select
  **Python 3.11**.
- Under **Virtualenv**, enter `/home/<username>/.virtualenvs/moviereviews-venv`.
- Under **Code**, set:
  - **Source code**: `/home/<username>/web-development-learning-lab/django-impatient/moviereviews`
  - **Working directory**: same path.

**7. Edit the WSGI configuration file** - the **Web** tab links to it
(something like `/var/www/<username>_pythonanywhere_com_wsgi.py`).
Replace its contents with:

```python
import os
import sys

path = '/home/<username>/web-development-learning-lab/django-impatient/moviereviews'
if path not in sys.path:
    sys.path.insert(0, path)

# Free-tier PythonAnywhere has no separate "Environment variables" UI
# (that's a paid-plan feature) - setting them here, before Django's
# settings.py is imported, is the free-tier equivalent. Never commit
# the real secret key value itself anywhere in this repo.
os.environ['DJANGO_SECRET_KEY'] = '<paste the value from step 5>'
os.environ['DJANGO_DEBUG'] = 'False'
os.environ['DJANGO_ALLOWED_HOSTS'] = '<username>.pythonanywhere.com'

os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'moviereviews.settings')

from django.core.wsgi import get_wsgi_application
application = get_wsgi_application()
```

Replace both `<username>` placeholders with your actual PythonAnywhere
username.

**8. Configure static/media file mappings** - back on the **Web** tab's
**Static files** section, add two mappings:

| URL | Directory |
|---|---|
| `/static/` | `/home/<username>/web-development-learning-lab/django-impatient/moviereviews/staticfiles` |
| `/media/` | `/home/<username>/web-development-learning-lab/django-impatient/moviereviews/media` |

Without these, Django itself won't serve either once `DEBUG=False` -
these mappings are PythonAnywhere serving those files directly at the
web-server level instead (faster, and what `STATIC_ROOT`/`MEDIA_ROOT`
in `settings.py` are for).

**9. Click the big green "Reload" button** at the top of the **Web**
tab, then visit `https://<username>.pythonanywhere.com`.

## Everyday workflow (redeploying a change)

No auto-deploy - after `git push`ing a change locally, in a
PythonAnywhere Bash console:

```bash
cd ~/web-development-learning-lab
git pull
workon moviereviews-venv
cd django-impatient/moviereviews
pip install -r requirements-pythonanywhere.txt   # only if dependencies changed
python manage.py migrate                          # only if new migrations exist
python manage.py collectstatic --noinput           # only if static files changed
```

Then reload the web app from the **Web** tab (or via PythonAnywhere's
API - see PythonAnywhere's own docs on the `webapps/.../reload/`
endpoint - if you want to script this last step with an API token,
which isn't set up here).

## Free-tier tradeoffs

- **No auto-deploy on push**, unlike Render/GitHub Pages - see "Why
  this is different" above. Every redeploy is the manual steps above.
- **No custom domain** on the free plan - only
  `<username>.pythonanywhere.com`.
- **Persistent disk**, unlike Render's free tier - `db.sqlite3` and
  uploaded `media/` files survive between reloads/redeploys without
  needing to be rebuilt, the opposite tradeoff from `data-serve`'s
  Render setup.
- **No spin-down** - unlike Render's free web services (which sleep
  after 15 minutes idle), a PythonAnywhere free web app stays up, so
  there's no "first request wakes it up" delay to expect here.
- **Outbound internet is allow-listed** on the free tier (PyPI is
  allowed, which is all step 3's `pip install` needs) - only relevant
  if this app ever made outbound HTTP calls itself, which it doesn't.
